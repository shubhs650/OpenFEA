# Domain model and persistence invariants

T014 adds append-only `analysis_mesh_setups` keyed by analysis/revision (migration `0007_mesh_setups`), with update/delete triggers. Canonical SI global/local sizes retain original source values/units and immutable geometry/catalog references, curvature and explicit recovery permission. Material/load/name/unit revisions copy controls; legacy revisions without rows read the declared default. Cleanup retains unresolved local refs; undo restores/rebinds captured controls. Job/deck snapshots freeze settings, quality policy and source fingerprints. Mesh preview-only success has its own complete manifest/host quality requirement, while solve still requires the full deck/native/result contract. Recovery records at most three profiles with exact unchanged sizing and per-attempt diagnostic hashes; the job is never automatically restarted. See [ADR-022](adr/ADR-022.md) and [mesh guide](MESH_CONTROLS.md).

UUID identifiers; UTC timestamps; dimensional canonical SI values; integer minor currency units or fixed decimals, never binary floating-point currency. Schema versions are explicit and migrations tested.

T007 implements `users`, `projects`, `geometry_revisions`, `analyses` and `analysis_revisions` with Alembic revision `0001_local_projects`. Local owner creation and revision writes are transactional; geometry/analysis history is append-only with UPDATE/DELETE triggers. Analyses inherit ownership through their project, and same-project foreign keys protect geometry/parent references. Project tombstones hide all child lookups. A draft without geometry is explicit, not runnable. The remaining entities below are planned. [ADR-015](adr/ADR-015.md) and [T007 evidence](validation/T007.md) describe the tested boundary; T008 must verify actual CAD artifacts before registering metadata.

T011 adds `local_jobs`, immutable `local_job_inputs`/`local_job_events` and terminal/identity guards (migration 0005_local_jobs). Admission freezes analysis/geometry/material/load/source/warning/tool policy plus completed mesh/generated deck identities; immediate transactions enforce ownership/current revision/idempotency/quota. Atomic FIFO claim, a single-active index, attempt token and OS/native execution lease fence publication. Active cancel is nonterminal until confirmed death; tombstones cancel atomically. Pending survives restart; interrupted attempts are fenced/retained without retry. Complete owned verified manifests link raw/parsed output to frozen inputs. See [ADR-019](adr/ADR-019.md) and [evidence](validation/T011.md).

## Consistency rules

T012 introduces no persistence migration: original T011 succeeded runs/raw artifacts remain immutable. A typed result view derives only from owned verified frozen input/mesh/deck/parsed/native artifacts, records processor version/source hashes and rechecks owner/tombstone after bounded processing. Body/material identity and separate raw-IP versus element-node semantics remain explicit; live material/yield/display edits cannot substitute original values. Missing/zero-stress yield factors use typed states and null. See [ADR-020](adr/ADR-020.md).

T009 adds append-only `analysis_material_setups` keyed by analysis/revision (Alembic `0003_analysis_materials`). Stored setup separates display preset from canonical per-body material snapshots, preserves source units/values and reviewed provenance, and resolves assignments only within pinned geometry. Empty legacy drafts are explicit. Name edits carry setup forward; unit-only changes copy all quantities exactly. Library version checks protect newly confirmed examples and library edits cannot mutate stored history. These are analysis snapshots; copying them into actual immutable runs remains T011. See [materials/units](MATERIALS_UNITS.md) and [ADR-017](adr/ADR-017.md).

T010 adds immutable `analysis_load_setups` per analysis/revision and `deck_exports` bound to an analysis revision (Alembic `0004_loads_decks`). Fixed/pressure/global total-force assignments pin both geometry UUID and deduplicated catalog face IDs, retain canonical/source values and explicit overlap confirmation, and carry forward through material/unit/name edits. Derived previews use native CAD area/centroid/outward normals; transient mesh/display identifiers are never stored as selections. Export records retain one frozen analysis/geometry/material/load snapshot plus policy/tool/source hashes and project-private content-addressed deck/mesh/snapshot blobs. Owner/tombstone/head is checked again before publication; old downloads read frozen bytes without live library/setup substitution. Legacy loads are explicitly empty. This is a bounded synchronous export bridge; durable jobs and immutable solve/run snapshots remain T011. See [loads/decks](LOADS_DECKS.md) and [ADR-018](adr/ADR-018.md).

A changed analysis creates a new revision and cannot change a queued/running snapshot. New meshes invalidate dependent derived previews. A run can reuse a compatible mesh only if geometry and all mesh controls/tool contract hashes match. Material/load changes do not require remeshing unless their selections require changed geometry, but always create a new run snapshot.
Duplication creates independent analysis state referencing immutable geometry. Archive import assigns new owner-scoped IDs and revalidates references; incoming owner IDs, URLs or executable scripts are ignored/rejected. Old immutable run snapshots may refer to an earlier geometry while the editor displays a newer one; UI must identify both.
Delete project first tombstones access and cancels pending work; purge only after active processes terminate. Audit manifests preserve deletion timing without retaining model content forever. Backup retention and erasure deadlines are disclosed.
SQLite transactions handle job admission, reservation and claim. Use WAL and busy timeouts; one control service initially. Live DB backups use the database backup API, not an unsafe copy of only the main file. Remote artifacts published only after a verified manifest; partial blobs are unreferenced until committed.

T013 adds `geometry_edits` (Alembic `0006_geometry_edits`) for persistent bounded preview/apply/undo records. Geometry and analysis/material/load revisions remain append-only; apply captures both optimistic heads, and undo restores the captured source in a fresh revision only while the applied heads are unchanged. Only one-to-one native-verified unchanged face maps transfer complete assignments. Other assignments retain original values/references with `review_faces` and block compute until explicit reselection/removal. The single body's material retains its exact source-backed snapshot. Old jobs/results retain frozen inputs; exact geometry UUID compatibility prevents old mesh reuse. See [ADR-021](adr/ADR-021.md) and [cleanup guide](GEOMETRY_EDITS.md).

T015 extends immutable load rows with face global component displacement and whole-body gravity, canonical/source quantities and explicit body-review refs (legacy defaults preserve existing rows). New import displays retain native volume centres. Cleanup invalidates gravity weight/body references; explicit reselection and undo append fresh snapshots. Run/deck policies freeze equilibrium criteria/load scales and source hashes; successful publication requires complete native artifacts plus both passing force/moment certificates. No migration rewrites old snapshots. See [ADR-023](adr/ADR-023.md) and [guide](ESSENTIAL_LOADS.md).

T016 extends immutable geometry metadata with native body-owned edge/vertex incidence and line/cylinder direction data; legacy catalogs default empty. Load rows retain signed direction/basis/origin/source geometry, scalar force/source units and per-face symmetry normals. Cleanup sets explicit direction/face review, with conservative reselection and guarded undo. No old snapshot rewrite or new migration. One compatible node frame is derived only after constraint consistency checks; native outputs/reaction spans stay global. See [ADR-024](adr/ADR-024.md) and [guide](GEOMETRY_DIRECTIONS.md).

T017 uses the existing append-only analysis/material/load/mesh tables for guarded historical setup restoration and conflict-only copies. It adds no migration and never accepts client-authored stored snapshots. Both operations check owner/live project/current head transactionally. Geometry identity must match for restore; copies preserve the observed geometry and exact SI/source/ref-review snapshots but inherit no jobs/results. Session undo targets and rejected commands are bounded browser memory only. Only the light/dark preference enters browser storage. See [ADR-025](adr/ADR-025.md).

T018 adds general saved/historical setup duplication through the same trusted transactional copy primitive as conflict recovery, using existing immutable analysis/material/load/mesh tables without migration. Each copy preserves the source's exact geometry UUID, SI/provenance and unresolved review refs, but receives a separate identity/head and no job/result/export records. Completed mesh jobs may be selected by another analysis only inside the same owned project after exact canonical compatibility and immutable-byte checks. The target's new solve freezes its own setup plus original mesh job/artifact/compatibility hashes; additive optional compatibility metadata does not rewrite earlier snapshots. See [ADR-026](adr/ADR-026.md) and [analysis guide](ANALYSES.md).

T019 adds append-only `analysis_bond_setups` per analysis/revision (Alembic `0008_bond_setups`); historical revisions before this migration explicitly read empty setup. Each assignment retains role/face and geometry UUIDs, canonical metre tolerance and separate gap/assumptions approvals, frozen native pair and complete policy/tool/source/isolation report, report SHA-256 and policy identity. Suggestions remain ephemeral until explicit approval; server repeats native review before transactional ownership/head/duplicate-face admission. Normal revisions, restore and saved/historical/conflict copies carry complete bond setup. Geometry mismatch preserves original references but marks review required; no proximity transfer. Immutable mesh snapshots include additive `bonds` with an empty legacy default, while physical mesh reuse excludes connections. Saved bonds require the T020 actual-mesh assembly admission and cannot be omitted by the deck generator. See [ADR-027](adr/ADR-027.md).

T020 adds no persistence schema. Existing frozen `DeckSnapshot.bonds` now participates in product component/mesh/deck admission. The same saved full report/role/geometry policy hashes govern connectivity; no inferred bond is persisted. `LoadState.assembly` exposes necessary component support diagnostics, while read-only actual-mesh preflight has no revision/job side effects. Successful run artifacts add immutable `assembly.json` and raw result/job-summary audits of mesh/review identity, exact intended dependent translations, native free equations, written coefficients and displacement continuity. Old inputs/raw outputs are not rewritten, and additive empty bond defaults remain valid for legacy snapshots. Failed numerical/output/equilibrium checks cannot publish results. [ADR-028](adr/ADR-028.md) records bounded solving and physical-gap limitations.

T021 adds no persistence or raw-result schema migration. The current-source result derivative includes typed field definitions, signed native node/IP extrema and two element-owned tensor/invariant views, with frame/order/body/material and smoothing contribution metadata. Derived fields are recomputed only from verified frozen run artifacts and original material assignments, including historical runs. Browser field, clipping and smoothing choices are display state; they never overwrite stored inputs, raw outputs, warnings or terminal records. See [ADR-029](adr/ADR-029.md).

T022 separates shared `ResultIdentity` from the surface `ResultView` and owned `ResultInspection`. The latter carries an explicit physical probe side or normalized section plane, interpolation version/method, element/body/material samples, barycentric positions, quadratic displacement and both tensor-derived modes. Interior points are not native nodes/IPs. Sections retain each intersected volume side, including coplanar interfaces. Browser camera/field/section state is temporary presentation state and does not mutate run artifacts or form a saved report view. See [ADR-030](adr/ADR-030.md).

T023 adds ephemeral `ResultComparison`/`ComparisonRequest` DTOs, not mutable run rows. A request binds canonical physical positions to explicit element sides in both frozen runs; the response retains both source identities, a physical-setup signature, field/mode, raw moving peaks, sampled changes, warnings and structured `AssumptionNote` explanations. Null relative changes/triggered states are meaningful and never replaced by finite safe/converged values. Downloaded JSON preserves positions and warnings; no persistence migration or stored convergence approval is introduced. See [ADR-031](adr/ADR-031.md).

T025 adds append-only `reports` via Alembic `0009_reports`, referencing the original immutable local job. `ReportRecord` holds private content hashes for model/HTML/PDF and renderer audit; project access derives from the job's original owner/tombstone. SQL triggers refuse replacement/removal. `ReportModel` shares frozen `JobInput`, `ResultIdentity`, original run/mesh summaries, explicit unit/view/camera/section definitions, trusted server SVG figures, unit-labelled fact tables, complete warnings/assumptions, optional checked physical comparison, source/tool/font/lock hashes and an attributed user conclusion. Binary outputs live in the existing private content-addressed store. No mutable analysis revision or raw result is rewritten. See [ADR-032](adr/ADR-032.md).

T026 adds `report_word_exports` via Alembic `0010_word_exports`, with immutable UUID/report reference/serialized `WordExport` and an index for owned history. Records bind the original report/run/project/model/PDF and generated DOCX hashes plus separate Word generation/version/resource provenance. Updates/deletes are refused; owner/tombstone access derives from the original job/project. Old `ReportRecord` and `ReportModel` schemas/bytes are unchanged. No analysis revision or new numerical result is created. See [ADR-033](adr/ADR-033.md).

T027 adds append-only `portable_bundles` and `archive_imports` via migration `0011_archives`. Both reference an owned project and retain strict immutable records. Imported project/geometry/analysis/load/bond/history UUIDs are new; physical SI/source values and source materials are retained, native geometry derivatives are rebuilt and references checked before atomic publication. Original historical file bytes/IDs remain separate inert provenance with explicit omissions, never inserted in executable job/result/report tables. Current native admission remains mandatory for a fresh solve. [ADR-034](adr/ADR-034.md) and [T027 evidence](validation/T027.md) describe hashes, rollback and privacy.
