## Real path delivered

The application now creates/opens persistent owned projects and performs a real bounded STEP upload → isolated OCCT inspection → explicit unit/size/body confirmation → atomic immutable geometry promotion → vtk.js rendering/picking. The native engine reads actual uploaded STEP; no mocked CAD, solver output, render coordinates or face IDs substitute for it. Accepted revisions and content-addressed source/BREP/body/display artifacts persist under the configured data root. Failed/stale/corrupted operations retain accepted geometry and earlier analysis references.

Native length metadata converts metre/millimetre/inch files to canonical SI. Missing metadata returns needs_units before shape transfer; a deliberate source-unit choice is then applied and the resulting metre dimensions must be confirmed. Known-unit conflicts, mixed/unsupported units, invalid/surface-only/free-wire inputs, excessive bodies/entities/faces and unusable tessellation refuse. An explicit empty shape-processing sequence disables optional repair. Canonical BREP is frozen before two display meshes are generated on separate copies, retaining original face identity through OCCT's copy mapping.

Uploaded parsing uses actual Bubblewrap namespace/readonly mounts, a private writable output directory, dropped capabilities, the verified no-network/resource launcher and a thread-only/fork/namespace/mount/ptrace filter. There is no unconfined fallback. Every inspection records binary/binding/python/filter/worker/lock hashes, runtime settings and warnings; private native transcripts remain in its import directory. Regular no-follow/hash-checked artifact reads, owned row lookups and guarded atomic promotion prevent path/stale/reference publication errors. An OS lock serializes application imports. Upload/import lifecycle persists; restart fails incomplete states without automatic retry.

The actual vtk.js canvas renders multi-body and curved native display triangles. Actor-to-catalog mapping resolves picks to immutable face/body identities in a geometry-revision context. Tests change camera, LOD and visibility, and verify known native centroids/body membership rather than only colors. Hover and selection differ; body hide/isolate and keyboard-accessible tree choices reach occluded faces. Rendering recenters coordinates before GPU buffers without changing canonical SI. The [inspected screenshot](results/T008/viewport.png) shows two real synthetic bodies with separately selected native faces.

## Implementation corrections and limits

Initial probes exposed OCP 8 binding differences: sequence/map type names moved to collections, a hasher-specific map is required, and bounding limits use corner accessors. Those paths were corrected and tested against real geometry. A local adjacency-loop error removed edge sets too early; removal now occurs after all neighbor calculations. Type/format errors were corrected before checks. Review added rejection of free wires/points so extra geometry is not silently dropped, plus a negative declared-unit override case. No missing dependency was skipped, solver mocked or numerical tolerance widened.

Final review added a project/BREP identity display guard, so replacing geometry cannot briefly associate old display data with a new revision. A real curved browser case delays the actual replacement response, verifies the guard, picks a native cap face and preserves it while the LOD triangle count actually changes. Confirmation replay keeps the original geometry and current project ETag; native/API regressions verify no duplicate revision.

Inspection is synchronous/bounded, with persisted lifecycle, not a durable asynchronous worker/queue. Display selection is ephemeral, not a saved load/material assignment or run snapshot. Current limits and sampled overshoot semantics are in ADR-016; they are not a certified arbitrary-model/laptop cap. Full hostile-file corpus, API-kill/fault recovery, root storage quotas, purge/retention/backup/restore and hardened hosted operation remain their later gates. Optional cleanup, material/load setup, meshing/solving and reports are not implemented here.

Windows/Edge/actual laptop/headed GPU, hosted CI, formal hash-bound benchmark acceptance, full release security/report suites and M1/M4 exit gates are **NOT RUN** in this task. Existing native regressions execute real tiny diagnostics; that does not approve broader assembly physics. The default `/tmp` data root can be removed by OS cleanup; choose durable local storage.
