# ADR-015: Local metadata persistence and revision scaffolding

Status: Accepted for T007 development
Date: 2026-10-13 (Asia/Calcutta)

## Decision

Use pinned SQLAlchemy 2.1.4 Core and Alembic 1.20.0 with SQLite WAL at `FEA_DATA_ROOT/metadata.sqlite3`. Startup applies versioned migrations inside explicit SQLite transactions. Foreign keys, a five-second busy timeout and FULL synchronous writes are enabled. Writes acquire `BEGIN IMMEDIATE`; ownership, tombstone visibility and expected revision are checked before committing changes in that transaction.

One persistent local user is created transactionally. No request header/body selects an owner. Project access is scoped by that identity; analysis and geometry access joins through its nondeleted project. Project deletion tombstones access while retaining metadata, including immutable child revisions. There are no jobs to cancel yet; job cancellation/purge coordination must be added with the actual job pipeline.

Geometry metadata is append-only, including source/BREP hashes, SI length declaration, confirmed source units, body/face catalog, parent, edit recipe and validation provenance. The CAD adapter must verify bytes and native validity before registration; T007 exposes only owner-scoped reads, not a browser endpoint accepting unverified geometry. T008 supplies import and artifact storage. Geometry record IDs are UUIDs; BREP content hashes remain separate. Catalog body/face IDs are scoped to that immutable revision, never persisted viewer triangles or Gmsh tags.

Analyses start as drafts with an optional geometry reference. Once present it is pinned to a geometry in the same project. Name edits append immutable analysis revisions and advance the head; old revisions survive edits/restarts. Geometry changes do not silently repin an existing analysis. Engineering settings, run freezing, duplication and editor undo remain their planned tasks.

Local API access requires a loopback peer and loopback Host. Browser Origin, when supplied, must match Host; cross-site requests are refused. GET `/api/v1/session` sets a process-lifetime HttpOnly SameSite=Strict cookie and returns the persistent owner plus a CSRF token. Metadata writes require the cookie and token; the cookie is intentionally HTTP-only local development without TLS, and is invalidated on API restart. The Vite proxy preserves Host, and the supervisor disables Uvicorn proxy-header trust. No local bypass is allowed in beta/production, which remain unsupported. This is single-user localhost access, not multi-user OS authentication or a hosted login system.

## Evidence and limits

[T007 evidence](../validation/T007.md) records real migrations, owner isolation, immutable histories, conflicting saves, a three-process HTTP restart and a Chromium/Vite project flow. Database triggers reject revision UPDATE/DELETE; scoped foreign keys reject cross-project references. Migrations reverse on populated synthetic metadata and a deliberately failed migration rolls back its schema.

SQLAlchemy/Alembic and their new transitive artifacts/licenses are retained in `uv.lock` and the [dependency inventory](../validation/dependencies.json). Native dependencies and physical criteria are unchanged. This decision introduces no hosted persistence, worker, archive/restore guarantee, CAD validity claim or M0 engineering acceptance. User authorization to implement T007 supersedes the older scheduling block while formal predecessor evidence remains pending.
