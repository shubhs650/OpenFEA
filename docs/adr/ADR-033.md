# ADR-033 — Editable Word exports of immutable saved reports

Status: Accepted for bounded local T026
Date: 2026-10-15

## Decision

Add a Word format export to an existing owned PDF report. Read the report's exact hash-verified `ReportModel` bytes rather than rebuilding facts from live setup or current result processors. The existing PDF, model, UUID, figures and warnings remain unchanged, including reports created in T025. Reverify the original retained run sources and any compared run at admission and publication. New Word exports refuse missing/corrupt sources; already generated DOCX downloads remain independently available while their own bytes and project access remain valid.

Append a separate `WordExport` record through `0010_word_exports`; never update the immutable `reports` row. Bind its report/run/project IDs, original model/PDF SHA-256, DOCX SHA-256, export time and actual generator/renderer identities. SQL guards forbid replacement/removal. Every list/read/download checks original ownership and project tombstones. The original shared report lock also admits Word generation, so PDF and Word rendering cannot race for this renderer. No automatic retries, cost approval or new analysis/job is introduced.

Use pinned python-docx 1.2.0 and lxml 6.0.2. PDF and DOCX share presentation helpers for overview, assumption status, continuation rows, attribution and reproducibility; each numerical table cell and caption comes directly from the same model. DOCX paragraphs, headings, captions and tables are native editable Word content. Figures are embedded 1,200-pixel PNG derivatives of the stored trusted SVGs, with the same camera/field/units/range/smoothing/deformation and legible legends; they are not editable engineering geometry. The current locked Chromium rasterizes them offline with DejaVu Sans. No user image/HTML/URL/document import is accepted.

Run both rasterization and python-docx in the existing private Bubblewrap user/PID/network namespace, with minimal environment and readonly runtimes/source/locked dependency mounts; only the private export scratch is writable. Keep the existing 45-second/1-GiB sampled RSS/64-MiB scratch watchdog and process-group cleanup. An inner Node deadline is 35 seconds. Retain output limits of 16 MiB, at most 64 ZIP parts and 32 MiB expanded package; reject external relationships, executable/encrypted parts and traversal. Reject XML-forbidden text explicitly rather than silently removing characters. Missing dependencies or failed generation publish no Word record and clean scratch.

A4 uses the same printable width/margins, repeating table headers, bounded continuation rows, fixed image width and captions. All warnings, assumptions, native extrema/checks and user conclusions remain present. Original report provenance and separate Word model/PDF references remain visible. The generated checksum identifies the original DOCX; later edits change that checksum and cannot acquire numerical certification. No computed safe-design finding is added.

## Verification and boundaries

`make test-reports` checks the exact archived T025 model, a 90-row Unicode layout fixture and the actual owned native-run API. It compares every table cell, warning, assumption and figure caption, verifies embedded image extents, edits/reopens paragraphs and cells, and converts generated DOCX through real isolated LibreOffice Writer for A4 text/page checks and visual inspection alongside the counterpart PDF. Ownership, CSRF, lock contention, failure cleanup, expiry, corruption, immutability, database reopen and tombstones are exercised. The actual browser generates/downloads Word and rediscovers it after reload. See [T026 evidence](../validation/T026.md).

LibreOffice Writer is a required verification dependency, not a production export service. Its actual version is recorded; conversion layout can vary across office implementations. Word on the actual Windows laptop and browser/headed/capacity acceptance remain T030. This does not implement archive import/export, uploaded Word execution or final redistribution approval. Numerical/benchmark criteria, native binaries and limits remain unchanged; only the two new Python packages and their lock artifacts are added.
