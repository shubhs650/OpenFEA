# ADR-025 — Acknowledged workspace edits and session recovery

Status: ACCEPTED for the bounded T017 local prototype
Date: 2026-10-14

## Decision

Use one small subscribed React store for the existing local editors. Keep locked dependencies unchanged: the architecture's proposed Zustand/Query adoption is not needed for this slice. Store only session identity, last acknowledged analysis revision, dirty editor keys, at most 50 undo targets and the exact rejected command in memory. Never persist engineering drafts, credentials or command history in browser storage. Persist only the light/dark preference; default to light and report storage failure.

Analysis names debounce for 700 ms; reviewed engineering values continue to require explicit Apply/Save. The shared mutation boundary distinguishes unsaved, saving, acknowledged, error and revision conflict. A failed/ambiguous response never advances the revision or adds undo. An explicit retry uses the original If-Match; a response lost after commit therefore conflicts safely. Unrelated writes refuse while another editor has a draft, except material-preserving display-unit conversion. Context switches are disabled during drafts; explicitly labeled reload discards drafts. Native job submission and geometry preview are excluded from setup history.

POST `/analyses/{id}/restores` appends a complete historical name/material/load/mesh setup using the current If-Match. It checks ownership/tombstone and both revisions inside one write transaction and refuses geometry changes, current/future targets and missing history. Undo consumes session command targets and uses the new head for subsequent undo. Geometry undo remains the existing separately guarded native edit command. Reload, context switch and geometry apply/undo clear setup history. Setup undo clears the displayed mesh/result and requires renewed review; it never edits admitted jobs or old raw artifacts.

A stale command offers reload or a conflict copy. POST `/analyses/{id}/conflict-copies` requires current source If-Match plus a strictly superseded observed revision. It copies trusted stored geometry/material/load/mesh snapshots into a new independent analysis at revision 1, with no jobs/results. The client then submits the rejected command to the normal validated editor route for the copy. Creation and command application are two distinct requests: application failure leaves an inspectable copy and cannot overwrite the original. This is the minimal T017 recovery path; general setup duplication, naming/selection management and comparisons remain T018.

The model checklist reads existing authoritative setup/preflight/job APIs, checks revision agreement and distinguishes saved setup from drafts. It never grants solve admission or treats readiness as numerical acceptance. Browser focus, keyboard face selection, geometry identities, raw results, unit semantics and server compute guards retain their existing boundaries.

## Verification and limits

[Evidence](../validation/T017.md) records state/transport/recovery, real browser/native/restart checks and target-size screenshots. Windows Chrome/Edge and owner laptop usability acceptance remain at M4/T030. Theme is a local browser preference in this single-user local stage, not a hosted account setting. Histories are bounded and session-local; no redo or cross-geometry setup restore is offered.
