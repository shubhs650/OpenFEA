# ADR-016: Confirmed STEP import and immutable vtk.js picking

Status: Accepted for T008 development
Date: 2026-10-13 (Asia/Calcutta)

## Decision

Add a real local STEP workflow to the T007 project API: size/hash ticket, bounded raw upload, isolated native inspection, explicit dimensions/body-count confirmation, and atomic geometry promotion. The inspection runs synchronously within a bounded request and persists its lifecycle; it is not a durable compute queue. T011 still owns asynchronous mesh/solve orchestration. The browser shows actual upload progress and a processing stage, with no fabricated processing percentage or automatic retry.

Use the pinned OCP 8.0.1.1.0 interpreter separately from Gmsh. Native `FileUnits` identifies length metadata and the reader's system unit is explicitly set to metres (`SetSystemLengthUnit(1000)` uses OCCT's millimetre convention). Recognized metre/millimetre/inch metadata converts natively. Missing metadata stops before shape transfer; an explicit user source-unit choice then applies the independently tested scale. Conflicting, mixed or unsupported units stop import. An empty custom FromSTEP shape-processing sequence disables optional repair operations; invalid geometry is rejected, not healed. STEP construction and unit conversion are ordinary import operations, not a general cleanup feature.

Only 1–10 valid positive-volume solids are accepted. Free surfaces, wires and points, excessive entities/faces and failed tessellation are diagnosed. Freeze canonical BREP and per-body BREP before generating display meshes. Separate deep copies generate coarse/fine tessellation; both retain original face identity through `ModifiedShape`. Catalog IDs bind to the canonical BREP hash and body/face indices within that immutable revision. The persisted geometry record also has its T007 UUID; selections operate within that revision context.

For uploaded bytes, use Bubblewrap namespaces and explicit readonly runtime/script/input mounts, a writable private output directory, dropped capabilities, and the existing verified no-network/resource launcher. An additional x86_64 seccomp filter permits threads while refusing fork and namespace/mount/ptrace operations. There is no unconfined fallback: missing Bubblewrap or unavailable namespaces fail closed. Preserve tool/binding/worker/filter/lock hashes, settings, warnings and private native transcripts. An OS file lock serializes application imports across threads/processes. Interrupted inspection/upload states fail on startup without retries. Native processes use parent-death behavior and are reaped on normal completion/failure.

Geometry artifacts are private content-addressed bytes under the data root and project UUID. Fixed names, no-follow regular-file reads, output bounds and hashes protect publication/access. Promotion verifies artifacts again and checks ownership, tombstone and project revision in one write transaction. Confirming the same promoted import is idempotent; no second geometry/revision is created. New geometry does not repin existing analyses. Physical purge, backup/restore and the unified job/cancellation system remain later work.

Pin vtk.js 37.4.2. Create one actor per catalog face and map picked actors to immutable face/body IDs, never retain a picked screen cell/triangle as identity. Rebuild actors on LOD changes while preserving camera and selection references. Display data must match the active project and BREP identity before it is shown; geometry replacement cannot reuse a stale display. Hide/isolate bodies changes actor visibility only. Rendering recenters metre coordinates before Float32 buffers, leaving canonical coordinates unchanged. Accessible tree face controls supplement mouse picking. This is display tessellation, not an FE mesh or numerical result.

## Evidence and limits

[T008 evidence](../validation/T008.md) records real native/API and Chromium flows, analytical dimension/volume checks, namespace/network/fork denial, stale confirmation, immutable artifact integrity, actual face picks after camera/LOD/isolation, and an inspected screenshot. Existing native mapping/stress/bond/resource regressions pass. No solver assumption, tolerance, native binary or native lock is changed.

Resource policy: uploads ≤16 MiB; ≤200,000 STEP entities, ≤2,000 faces, ≤120,000 triangles per LOD; 60 s wall/CPU, 4 GiB native address-space hard limit, 1,536 MiB sampled tree RSS guard, 192 MiB sampled scratch/output guard plus bounded directory scanning, and 64 MiB per-file native hard limit. Polling can overshoot; the limits are admission/protection policy, not arbitrary-model/laptop capacity certification. Disk reserve is 1 GiB. Final output size is checked even when a process exits between samples. Stored artifacts are individually limited to 32 MiB.

The browser and API now operate on real imported geometry. Materials, loads, meshes, solving, cleanup, durable queue, persistent engineering assignments and reports are still their scheduled tasks. Windows/Edge/target-GPU and formal engineering benchmark acceptance remain deferred by the [owner decision](../validation/M0-owner-decision.md). No hosted service, cloud resource or final distribution license is approved here.
