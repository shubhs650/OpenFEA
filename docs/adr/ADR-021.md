# ADR-021 — Bounded product cleanup with conservative face review

Status: Accepted for T013 development
Date: 2026-10-14 (Asia/Calcutta)

## Decision

Expose the existing M0-supported selected-feature removal through real owned preview/apply/undo routes and the workspace. Keep the exact two analytical unit-solid cases in [ADR-014](ADR-014.md); do not broaden physical scope from a successful kernel return. Read the canonical immutable BREP, verify its hashes, select the native face from the stored revision catalog, deep-copy geometry and topology, and execute OCCT `BRepAlgoAPI_Defeaturing` with parallel execution disabled. Verify validity, one positive-volume solid, six planar result faces, unit volume and the original analytical feature-volume delta. Verify symmetric solid differences against the declared source/reference/result. Preserve the 1e-10 m³ development criterion. Source files are read-only inside the existing Bubblewrap/network/process-filter sandbox and are hash-verified before and after execution, including failure.

Reuse the native import exporter for actual SI body/face catalogs, correctly oriented pressure normals, body BREP and coarse/fine face-labelled tessellations. Preserve original source-unit confirmation/source STEP identity; add the cleanup recipe, native runtime/source hashes and warnings. The two native shape candidates use the exact M0 construction. A changed feature radius or a split face topology refuses. This is an explicit bounded capability, not general healing or arbitrary imported-feature validation.

A face may transfer only when surface type, orientation/plane normal, bounds, area and **both native full trimmed-face differences** agree within 1e-10 (m for bounds, m² for area/differences, dimensionless for normals), and the candidate is unique in both directions. Signatures alone are insufficient; no index/tag/triangle identity or centroid-only nearest-neighbor map is accepted. Retain a complete source-face map with `unchanged`, `removed` or `changed_or_ambiguous`. Split/merged, removed and uncertain references require explicit review. Server-side publication verifies complete source coverage, target membership, unique targets and status/target consistency. T013's fixed development thresholds do not change existing signed benchmark criteria.

Apply uses the captured project ETag and optional analysis identity/revision. Recheck ownership, tombstones and both revisions after native preview, then again inside the atomic apply transaction. Append geometry and optional analysis/material/load setup revisions together. Transfer the single material-bearing body with provenance intact; leave other analyses on their original geometry. A load/support transfers only if its entire face selection is unchanged. Otherwise retain the whole original assignment and exact SI/source quantities with `review_faces`; do not redistribute a total force over the surviving subset. List the exact unresolved faces and block export/mesh/solve. Suppress invalidated arrows and preview resultants. Explicit reselection retains magnitude/sign/global direction and enforces current face/geometry membership, planar pressure and load overlap checks.

Undo appends a new geometry revision referencing the original verified artifacts and restores the captured immutable analysis setup, rebinding valid assignments to that revision UUID. Require the unchanged applied project and analysis heads. Repeated same-command apply/undo replays without adding revisions; stale later edits are not overwritten. `0006_geometry_edits` stores persistent preview/lifecycle records; existing history/run tables and triggers remain unchanged. API restart preserves records; the browser undo control is session-only.

Mesh compatibility already requires exact geometry UUID and tool contract; no geometry edit can reuse a prior mesh for new solve admission. Existing jobs and results keep their frozen snapshots. The viewer selects the result's own frozen body visibility when the live geometry differs. Cleanup previews use their new body's identity for rendering; before/after highlights and unrelated live face picking are separated while preview is active. No queued work is cancelled or rewritten by cleanup.

## Evidence and boundaries

[T013 evidence](../validation/T013.md) and the [operator guide](../GEOMETRY_EDITS.md) retain actual hole/fillet previews, analytical volume errors, split/unsupported refusals, assignment blockers/reselection, real meshing/CCX, old result history, owner/CSRF/corruption/concurrency checks, restart persistence and rendered browser evidence. Existing pipeline limits and native/dependency locks are unchanged. New material/face reassignment choices require explicit user action; automatic repair, broader defeaturing, directions/sizing/assemblies/reporting remain dependency-ordered later work. Signed engineering benchmark, target laptop/Windows/Edge/headed GPU and M2–M4 exit acceptance are not claimed by this task.
