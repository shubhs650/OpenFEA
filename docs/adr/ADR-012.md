# ADR-012: Raw integration stress and element-owned display fields

Status: Accepted for development implementation; engineering-owner benchmark acceptance pending
Date: 2026-10-13 (Asia/Calcutta)

## Decision

Use pinned CCX 2.23 `*EL PRINT,ELSET=EALL,GLOBAL=YES` with `S,COORD` for authoritative raw integration-point stress tensors and native global positions. Generate these requests internally; the adapter supports one linear-static step/increment at time 1, affine C3D10 and ASCII output. Unsupported frame/layout/type or incomplete output is rejected, not guessed. The file header, entity coverage, four IPs per element, printed coordinates, frozen mesh and component order must agree.

DAT order is `xx,yy,zz,xy,xz,yz`; canonical order is `xx,yy,zz,xy,yz,zx`. Store the source order and permutation explicitly. Raw samples carry element/IP, body/material, global coordinate/frame, SI units, source file/hash/line (including COORD line), parser version and mesh hash. Nodal U and RF retain their distinct semantics; RF is external force, not automatically a support reaction.

The pinned manual describes FRD `*EL FILE S` as extrapolated nodal averaging, including material-interface smearing. Read the demonstrated ASCII layout with canonical `SXX,SYY,SZZ,SXY,SYZ,SZX`, validating time, node/element coverage, geometry/connectivity/material and completion records. Label this field `solver_averaged_node`, with all contributing element IDs. It is a diagnostic comparison, never a source of unaveraged tensors or material-side values.

For affine isotropic C3D10, recover a linear stress field from its four Gauss tensors. Use the exact four-point barycentric matrix from pinned `gauss.f`, extrapolate to each element's four corners, then interpolate its six midsides. Mark results `element_node` with method `linear_C3D10_extrapolation_from_native_DAT_IP`. This is derived, not native element-nodal output. Keep a separate `(element,node)` value, including at shared nodes. Probes require an explicit element side and barycentric position and use location `element_interpolated`. Refuse stale mesh/frame/component or body/material ownership.

Compute von Mises from all six components and sorted principal stresses using scaled symmetric Jacobi rotations. Repeated-root cancellation found in the initial analytic `acos` method was fixed without relaxing tests.

Native VTK exports duplicate all ten nodes per C3D10 cell and retain global node/element/material/body IDs, tensors and provenance. A separate VTP stores raw IPs. The minimal standalone HTML/SVG fixture shows two labelled views of B09's shared face and native-versus-derived tables; it is an offline scientific diagnostic. The proposed vtk.js product viewer, full 3D interaction, sections and production contour UI remain later work. No new dependency or health-app change is introduced.

## Evidence and scope

[T004 evidence](../validation/T004.md) contains a real two-material shared-node solve, hydrostatic/pure-shear/varying-shear tests, damaged-output failures, exact VTK round-trip and Chromium inspection. DAT preserves 210/70 MPa material values; native FRD gives approximately 140 MPa on shared nodes. No own averaging crosses element, body or material boundaries.

The user requested T004 while T003 engineering review was deferred. This authorizes bounded development work; it does not approve B01/B02/B09 or close M0. T003/T004 formal acceptance remains open. Curved elements, plastic/nonlinear/multi-step/local-frame/binary output and arbitrary upload parsing are outside this validated adapter. No solver patch, stabilization, fake stress, tolerance widening, tie, deployment or merge is used.
