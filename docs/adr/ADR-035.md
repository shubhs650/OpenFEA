# ADR-035 — Bounded local attempts and reusable solver stages

Status: Accepted for T029 local development
Date: 2026-10-16 UTC

## Decision

Extend the existing embedded worker and SQLite queue, without a remote scheduler or new analysis types. Migration `0012_job_attempts` adds a durable attempt ledger and one immutable native-stage checkpoint. Backfill existing claimed jobs without changing terminal rows or frozen input bytes. Terminal logical jobs and finished attempts remain immutable. Attempts have distinct tokens and private `attempt-1` / `attempt-2` directories. Owned job reads expose both attempts, the original deadline and diagnostic hashes; fixed-name attempt downloads and portable inert archive attachments retain their bytes.

A logical job receives one 180-second deadline on its first claim. It includes validation, recovery, restart downtime and waiting for its retry; initial queue wait is excluded. Each live attempt also enforces its remaining allowance with a monotonic clock. Claim, cancellation and completion use immediate transactions; no retry resets the original start/deadline. Cancellation, deletion and ownership loss win before retry/publication. A job may have at most two infrastructure attempts, with the old attempt marked interrupted before the same logical job returns to queued. It never becomes terminal and then runs again.

Eligible interruptions are controller shutdown/death, expired execution heartbeat and observed parser SIGTERM. Unknown parser exit, SIGKILL (including possible kernel OOM), corrupt output/checkpoint, numerical/model failure and resource refusal are terminal/review failures. No automatic user/model failure retry. An expired ten-second heartbeat rejects new pulses, checkpoints and successful publication; it does not establish process death. The controller first acquires the exclusive worker lock, fences recorded boot-ID/start-time process instances, and waits for the inherited native execution flock. Only after that can recovery queue another execution. A live supervisor kills/waits its owned native group before recording interruption. A control or fencing error blocks further claims.

After actual CCX exit, retain bounded hash-verified log, DAT, FRD and host resource record as a token-guarded immutable checkpoint tied to the original input identity. A later attempt checks the identical frozen source/tool policy and all saved hashes/sizes before restoring those raw bytes. It then runs validation only. Missing/corrupt committed checkpoints fail without another CCX launch. Uncommitted partial output is diagnostic; an interrupted native stage can be executed again after fencing. This is a bounded recovery protocol, not a general exactly-once external-command guarantee.

Move existing DAT/FRD, assembly and external force/moment validation into a fixed Python command under Bubblewrap, netdeny and the existing process filter. It mounts only frozen input, mesh, generated deck and raw outputs readonly, plus source/runtime libraries readonly and private writable validation scratch. It has no database/project-store access, network or subprocess escape. The controller continues heartbeat/cancellation/resource supervision throughout parsing. Deterministic validation errors return a bounded data-only outcome and never trigger infrastructure retry. Preserve the original physical algorithms, criteria, numerical errors and diagnostics. Results publish only after all existing validation and complete artifact checks pass.

## Envelope and consent

Keep 60 seconds per native stage, sampled process-tree RSS 1,536 MiB, aggregate logical-job scratch 192 MiB, and a 1 GiB free-disk reserve checked before/during/after native execution. Add an 8 MiB log cap and 64 MiB of unique retained artifact bytes across checkpoints and both attempts; each artifact read remains at most 32 MiB. Retain existing hard CPU 60 s, address space 4 GiB and per-file 64 MiB launcher limits. Live sampling is every 50 ms and final disk/log audits include short-lived writers. Sampled limits can overshoot between observations; these are not cgroup or filesystem quotas. The bounded scratch scan still refuses over 128 entries; its depth accommodates the two additional execution-directory levels.

The deadline and aggregate storage bounds dominate infrastructure retries and approved mesh recovery profiles. Resume at the interrupted mesh profile; do not repeat earlier failed profiles or change sizing. Initial plus two distinct numerical profiles still require the existing explicit saved recovery consent. A coarser mesh requires an explicit user edit/review and new frozen inputs, invalidating old mesh-dependent results. No automatic coarsening, healing, stabilization or bond approval.

The measured T006 envelope informs these conservative limits; it does not establish universal factorization capacity. Preserve the product 3,000-element ceiling. The previous 99,198-element diagnostic exceeded the 30k/120k-DOF solve admission guard and was not solved. Do not repeat a 100k solve as a T029 safety claim; actual laptop capacity remains T030.

## Verification and limits

[T029 evidence](../validation/T029.md) records real parser termination/repeated retry/cancellation, stale heartbeat, disk pressure, measured watchdog stops, API kill/restart, raw-byte reuse and visible browser history. Fault injections are synthetic process-control tests, not numerical acceptance or actual host disk exhaustion. Existing full native/analytical/assembly checks retain their criteria. No dependencies, binary hashes, engineering-owner approvals, native capacity or individual test deadlines change. CI separates core/native and application coverage within the same 25-minute job deadlines; full native regression still runs once. Hosted billing, cross-host leases, quota/retention lifecycle and actual Windows/WSL2/headed laptop acceptance remain outside this task.
