# Workspace checklist and safe edits

The left model checklist links to geometry, materials, supports/loads, mesh and runs/results. You may revisit valid setup in any order. Each step describes acknowledged data and gives the next action or the actual server preflight blocker. “Ready” is setup readiness; actual native quality, support, mapping and equilibrium checks still govern execution. Earlier results remain frozen to their own revisions.

The save state above the viewport reports unsaved drafts, saving, saved revision, failure or conflict. Names autosave after a brief pause. Materials, loads, directions and mesh controls retain explicit review and Apply/Save. Cancel each editor's draft to return to saved values. Another setup write is refused if it would discard a different editor's draft. Switching project/analysis/body is disabled during affected drafts; use Apply/Save, Cancel or an explicitly labeled reload. No draft or failed request is labeled saved.

A failed or ambiguous response retains the rejected command. For a failed name autosave, “Retry unacknowledged edit” explicitly retries the latest rejected name with its original revision guard. For engineering inputs, review and Apply/Save the current draft again. If another session changed the analysis, reload the saved workspace to discard drafts, or use “Duplicate my conflicting edit.” This copies your previously observed setup and applies the rejected edit through the regular validated API in a separate analysis. The original stays unchanged. If copying succeeds but application fails, the rejected draft stays open on the original analysis. A separately labeled button opens the created copy and explicitly discards that rejected draft; do not infer success from creation alone. General analysis duplication/management remains T018.

“Undo last setup edit” restores the preceding command's name/material/load/mesh snapshot by appending a fresh revision. It covers up to 50 acknowledged setup edits in this session and is disabled until drafts are resolved. Multiple undo commands use the new head each time. Reload, analysis/project switches and geometry changes clear the stack. An external edit causes undo to refuse rather than overwrite it. Geometry cleanup has its separate guarded Undo geometry edit flow. Mesh/result previews clear after setup undo; old admitted jobs, downloads and completed results remain immutable.

Tab to face buttons in the body tree; Space/Enter toggles each face without clearing other selections. Arrow Up/Down moves between visible face buttons, Home/End moves to the first/last, and Escape clears selection outside text controls. Text fields retain their normal keyboard behavior. Checklist buttons move keyboard focus to the actual editor. Hidden bodies remain available through the tree.

Light is the default theme. The Theme select applies dark/light tokens to controls, warnings, tables and the actual CAD/results viewport. The preference persists in this browser and synchronizes between its tabs. If storage is blocked, the choice still applies for the visit and a message explains that it cannot persist. No credentials or model data are stored with the preference.

[ADR-025](adr/ADR-025.md) defines the recovery and state contract. [T017 evidence](validation/T017.md) distinguishes executed Linux Chromium checks at 1280×720/1366×768 from pending owner laptop/Windows Chrome/Edge acceptance.
